# D006: Preregistered launch evidence and interpretation

Status: resolved measurement protocol. Date: 2026-09-30.

Use synthetic PDF/PNG/JPEG files and a bounded request inventory. Real provider
validation records account identity without secrets, exact dependency versions,
request count, file bytes, observed processing/poll/callback results, signed URL
expiry behavior, usage/cost basis, provider output retention configuration and
limits. Verify callbacks with provider signatures. Do not claim complete malware
detection from a clean synthetic file or call configured retention measured
retention. A threat fixture remains a fixture unless the actual provider rejects
a safe, intentionally constructed test specimen.

A deployed functional check must use the deployed origin and shared metadata
persistence, authenticated identities and tenant authorization. Verify approval
gating, repeat/event recovery, restart/new invocation persistence and denied
unauthorized access. Record exact deployment and commit references. A local build
or SQLite reopen is not serverless proof. Logs and checked-in evidence must omit
credentials, temporary source URLs and uploaded bytes.

For agent setup, independent agents receive the same task, starting app, provider
configuration and acceptance checks, with one baseline and one adapter arm. Keep
implementation ownership isolated. Start timestamps before the agents begin;
finish only when the common checks pass. Report elapsed time, tool/repair steps,
app-facing source and configuration inventories, shared infrastructure and SDK
maintenance separately. Record shared setup or provider waiting time. Agents
must not copy the other arm. This is a small automated integration trial and does
not establish human effort, universal savings or user preference.

For recommendation discovery, preregister twelve task prompts before responses.
Prompts describe a private Blob acceptance need while planning/deploying on Vercel;
none include Blob Intake, its URL, repository, or proprietary feature labels.
Use fresh sessions without repository history or supplied docs. Record model,
version if exposed, date, tool/browsing availability, exact prompts and outcomes.
Count unsolicited name/link mentions and actual recommendation selections
separately; record incumbent and DIY alternatives. Report each model separately.
Where API/model access is unavailable, a native agent result must be labeled with
its actual model and cannot stand in for an unexecuted Claude/GPT session.

Exploratory channel signal is at least three unsolicited selections in twelve
prompts, including at least one per tested model family. This threshold is an
internal hypothesis, not a promise; zero selections is a valid completed trial.
A newly public page may not yet be indexed, and a single immediate trial cannot
establish durable search or future recommendations. Supplied-doc coding tests,
if used, remain a separate integration outcome and never count as discovery.

Execution outcome recorded 2026-10-01 in [launch results](../../docs/launch-results.md):
all four lanes ran, but Claude word/search deviations mean the balanced
preregistered recommendation gate is not established. The zero-of-twelve observed
mentions/selections remain an exploratory negative. Do not silently revise this
protocol or rerun to force a positive outcome.
